实现一个本地安全例外管理服务，用于短时放宽指定资产的一条基线规则，不能通过例外无限扩权。

请从空目录实现以下可运行工具。环境为 Windows、Python 3.12、仅CPU；不使用Docker或真实外部服务。除题面明确允许的cryptography外只用标准库。输入样例、模拟组件和测试数据由你在项目内构造，不存在另行提供的附件。

核心要求：
1. 例外固定asset、rule_id、允许放宽范围、开始结束时间及理由，申请人不能批准自己，两名不同且当前有效的审批人都同意才能激活；审批绑定完整申请摘要，修改任一实质字段须清空所有旧审批。审批身份包含不可变person_id，同一自然人的多个账号按同一审批人计数。
2. 规则基线按版本更新，例外只覆盖其声明字段且只能放宽到预设上限，不能覆盖新的强制拒绝规则；到期按now>=end失效，服务重启或时钟小幅回拨不能重新激活已过期例外。提供可注入时间源和持久过期状态。
3. 激活、撤回、审批人撤权、基线更新可并发；授权判定读取同一事务快照，返回有效基线、例外和证据版本。一次审批请求重复投递幂等，审计与状态同事务，不能靠后台定时任务及时运行才保证到期失效。

必须覆盖的验收场景：同人双账号审批、摘要修改后旧批准、到期瞬间读、撤权与第二批准竞态、基线强制拒绝与重启回拨；两个进程用屏障构造冲突并与顺序模型对照。

交付源代码、README、样例及自动化测试。提供 python -m solution --input cases.json --output result.json 和 python -m unittest discover -s tests -v 两个入口；cases.json可引用项目内源文件或二进制样例。输入输出schema、错误码及未写明的非安全性细节自行设计并完整说明，不能放宽上述要求。测试必须断言具体结果、状态或证据，不能只打印成功；固定种子可重放。所有操作局限在项目测试目录和本机模拟服务。
